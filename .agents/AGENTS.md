# AI Coding Agent Dispatcher

**CRITICAL RULES:**
1. **MAP FIRST:** `.agents/maps/code_map.md` lists every Kotlin file with its purpose, size, and declarations as `name:line`. Grep it for a feature word (e.g. `Rating`, `Loan`, `timer`) or read the section for the domain, then `Read` the target file with `offset`/`limit` at that line. Do not grep the source tree or read big files whole until the map has failed you.
2. **KEEP IT FRESH:** After adding, renaming, moving, or deleting a file, class, or function, run `npm run update-maps`. `npm run check-maps` exits 1 if the map is stale; the pre-commit hook in `.githooks/` runs it (enable once per clone with `npm run install-hooks`).
3. **Historical architecture notes:** `docs/ARCHITECTURE_HISTORY.md`. DO NOT modify it.

## Change X -> touch these files
Paths are relative to `app/src/main/java/com/example/booktracker/` unless they start with a module name.

- **New/changed stored field on Book, Session, or MarginNote:** `shared/.../models/Models.kt` (domain) -> `app/data/local/Entities.kt` -> `app/data/local/Mappers.kt` (toModel/toEntity) -> `app/data/local/AppDatabase.kt` (bump `version`, add `MIGRATION_n_n+1`, register it) -> `app/data/BackupEngine.kt` (`toJson`/`toBook`/`toSession`/`toNote`; bump `FORMAT_VERSION` if old backups need handling). Add DAO queries in `app/data/local/Daos.kt` only if you query the field.
- **New screen / route:** add a `composable("route")` in the NavHost in `app/ui/BookTrackerScreen.kt` (routes are listed in the map). The five bottom-bar sections are not routes: they are pages of the `HorizontalPager` inside `composable(MAIN_ROUTE)`, ordered by `TAB_ORDER`; switch with `navigateTopLevel("library")`, never `navigate("library")`. state/actions in `app/ui/BookTrackerViewModel.kt`, data via `app/data/BookRepository.kt` (interface + `RoomBookRepository`).
- **New user setting:** `app/data/SettingsRepository.kt` (key + setter) -> `app/ui/BookTrackerViewModel.kt` (setter) -> `app/ui/SettingsScreen.kt` (opened from the gear on Profile), or `app/ui/GoalsScreen.kt` if it is a reading target, day rule or reminder. If it should survive backup/restore, also update the `settings` block in `app/data/BackupEngine.kt`. A small on/off or choice usually belongs in `AppPrefs` instead of its own key and setter: add the field and its line in `PrefKeys`/`readPrefs`/`updatePrefs`, set it with `viewModel.updatePrefs { it.copy(...) }`, and read it in UI through `LocalAppPrefs.current`.
- **Stats / goals / streaks / badges / loans:** pure engines in `app/analytics/` with unit tests in `app/src/test/.../analytics/`; shown in `app/ui/AnalyticsScreen.kt`, `HomeDashboard.kt`, `ProfileScreen.kt`.
- **Badges / monthly challenge:** `app/analytics/BadgeEngine.kt` (each badge is a `measure` against a `target`; earned dates are replayed from history, not stored) -> `app/ui/AchievementsScreen.kt` (full gallery) and the teaser card in `ProfileScreen.kt`.
- **Wrapped:** numbers in `app/analytics/WrappedEngine.kt`, story slides in `app/ui/WrappedScreen.kt`.
- **Visual system:** type in `app/ui/theme/Type.kt` (Fraunces for display/headline/titleLarge, Inter for the rest; bundled in `res/font`, licences in `assets/licenses`). Corners only from `AppShape` (`app/ui/theme/Shape.kt`: XS 8, S 12, M 16, L 20, XL 28), never a hand-typed `RoundedCornerShape(n.dp)`. Icons are `Icons.Rounded` (not Filled/Default). Covers through `BookCover(book, modifier)` (`app/ui/BookCover.kt`; typesets a cover when there's no art). Confirmations and small pickers are `ActionSheet` (`app/ui/ActionSheet.kt`), not `AlertDialog`. A book's own colour comes from `rememberCoverAccent` + `Modifier.coverGlow` (`CoverPalette.kt`). Lists animate in with `staggeredItem`/`staggeredItems` (`Motion.kt`).
- **Section headers / bottom bar:** each of the five sections wraps its content in `SectionPage` (`app/ui/SectionHeader.kt`): a big title with a live line that collapses into a slim bar on scroll; there is no shared top bar on the main sections. On phones and portrait tablets (COMPACT and MEDIUM) the bottom bar (`FloatingNavBar.kt`, with the Add button beside it) floats over the sections and hides on scroll down, so a section's scrolling content must end with `LocalNavBarClearance.current` of bottom padding.
- **Motion / haptics / celebrations:** reuse `app/ui/animations/Motion.kt` (timings, springs, `rememberHaptics()`, `rememberReduceMotion()`, `animateCountUp`, `staggeredEntrance`, `swipeToAct`) rather than ad-hoc tweens. Screen transitions live in `NavMotion.kt`; flame and sky in `Ambient.kt`; bursts in `Confetti.kt`. Loops and particles must stay still when `rememberReduceMotion()` is true; drive them from `rememberAmbientClock` (`Ambient.kt`), which also rests them a few seconds after the last touch and keeps them still on low-end phones (`AmbientWakeHost`). Use `TickFilterChip` for filter chips.
- **Reading timer:** `app/service/TimerService.kt` (foreground service + persistence), `app/ui/FocusTimerScreen.kt`, then `SessionSaveScreen.kt` -> `SessionResultScreen.kt`.
- **Home-screen widgets:** `app/widget/`, one `GlanceAppWidget` + receiver per widget. Data comes from `WidgetData.load`, bitmaps (rings, pixels, covers) from `WidgetArt`, and taps open screens through `DeepLink.intent(route)`; a new route must be added to `DeepLink`'s allow-list. Register each receiver in `AndroidManifest.xml` with a `res/xml/*_widget_info.xml` and add it to `WidgetRefresher.widgets()`, which redraws them all when data changes.
- **Daily review / vocabulary:** scheduling in `app/analytics/ReviewEngine.kt`; progress in `review_states` and words in `vocab_words` (`ReviewDao`, `VocabDao` in `app/data/local/Daos.kt`); screens `ReviewScreen.kt` and `VocabularyScreen.kt`, reached from Home and the Notes tab.
- **Wishlist:** a book is wished for when `ownership == WISHLIST`; its details (priority, price, store, release day) are `Book.wish`, separate from reading status. Wished books aren't on the shelf: any list or count of the reader's own books (Library grid, Up next, to-read swipe, widgets, recommendations) goes through `WishlistEngine.onShelf`; the Library never shows them (no tile, no ownership filter); the wishlist is reached from the bookmark button beside the view toggle in the Library, the Wishlist tile in Home's Shortcuts and its own route. Pure logic (sorts, totals, series gaps, monthly spend, release days, share text) in `app/analytics/WishlistEngine.kt`; the page, editor, "Got it" flow and budget in `app/ui/WishlistScreen.kt` (route `wishlist`); release-day notifications in `WishlistReleaseWorker` (`app/worker/NudgeWorkers.kt`).
- **Finish-by plans / re-read memories:** pure logic in `app/analytics/FinishByPlanner.kt` and `RereadMemories.kt`; cards in `app/ui/ReadingPlanCards.kt` (book page, Home card line, session recap).
- **Phone <-> watch sync:** paths and keys in `shared/.../Constants.kt`; phone side `app/sync/WearBridge.kt` (send; started from `BookTrackerApplication`, not the ViewModel, so the watch works with the app closed) and `WearSyncService.kt` (receive). Publish only on change: the timer goes as an anchor time and the watch counts the seconds itself. Watch side: `WatchStore.kt` is the one read/write path (phone data plus unconfirmed local taps, LWW) for `WearActivity.kt`/`WearScreens.kt`, `ReadingTileService.kt` and `GoalComplicationService.kt`; a session timed on the wrist (`WristSession.kt`, with its Ongoing Activity chip) holds its page taps and goes to the phone whole, saved by `BookRepository.addRemoteSession`. After a watch-side data change call `WatchStore.refreshSurfaces` so the tile and complication redraw.
- **Tablet / large-screen layout:** read `LocalWidthTier` (from `app/ui/Adaptive.kt`; it follows the window, so split-screen counts as a phone) instead of the screen size. Cap text screens with `Modifier.readableWidth()` (scroll columns) or `windowCentredPadding()` (lazy-list content padding), and size cover grids with `coverTileMinWidth()`. Book pages go through `BookDetailRoute` (phone route and library pane). In landscape the sections sit beside a side strip: a rail, or on LARGE a drawer the reader folds to the rail (`sideNavCollapsed`, its own setting, not `AppPrefs`); offset content by `navChromeWidth()`. Right-click, image drop and text drag helpers live in `TabletInput.kt`; the foldable hinge in `Posture.kt`.
- **Wiring / singletons:** `app/data/ServiceLocator.kt` (manual DI, no Hilt).
- **Startup profile:** `app/src/main/baseline-prof.txt`, recorded by `:baselineprofile` (`BaselineProfileGenerator`: cold start, then Home, Library and a book page, Notes, Stats, Profile). Re-record after big UI changes with `npm run baseline-profile -- <adb-serial>` (Android 13+ device) and commit the file. It drives the app's `benchmark` build: a separate `.benchmark` package, unminified, seeded by `app/src/benchmark/.../DemoLibrarySeeder.kt`, so a reader's own install is never touched. If a new first-run dialog or screen appears, the seeder must get past it too.
